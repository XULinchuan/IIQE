# 微信个人号回复助手设计（V1）

- 日期：2026-03-17
- 状态：Design Approved by User（conversation）
- 目标平台：Mac 版微信 + iPhone（仅本人安装，不上架）

## 1. 目标与边界

### 1.1 目标
构建一个“微信个人号回复助手”：
- 在 Mac 端对指定会话自动轮询并检测新消息。
- 基于会话上下文调用 OpenAI 生成候选回复。
- 将候选回复同步到 iPhone 独立 App。
- 用户在 iPhone 点“复制回复”，再回微信手动发送。

### 1.2 明确边界
- 不在 iPhone 端直接读取微信消息。
- 不自动发送微信消息。
- 允许聊天内容上传到云端模型（OpenAI）。
- 依赖 Mac 微信在线且窗口布局固定。

### 1.3 V1 范围
- 支持 3 个会话轮询（后续可扩展到 5 个）。
- 生成 2-3 条候选回复。
- 支持全局风格、会话级风格覆盖、即时改写。

### 1.4 V1 非目标
- 群聊复杂说话人解析。
- 多微信账号并发。
- 自动化发送或半自动注入到微信输入框。
- 知识库 RAG（文档检索增强）能力。

## 2. 方案比较与选型

### 方案 A（选中）：Mac 轮询采集 + 云端生成 + iPhone 收件
- 通过 Mac UI 自动化 + OCR 采集指定会话新增消息。
- 调 OpenAI 生成候选回复。
- 通过同步服务推送/拉取到 iPhone App。

优点：
- 无需越狱，不改微信客户端。
- 满足“指定会话后自动轮询”的核心诉求。
- 在合规和可维护性间平衡最好。

缺点：
- 依赖微信桌面 UI 稳定性。
- OCR 质量受字体、缩放、主题影响。

### 方案 B：Mac 插件/逆向注入
优点：自动化程度高。  
缺点：封号与合规风险高，维护成本高。  
结论：不采用。

### 方案 C：手动快捷键抓取 + 云端生成 + iPhone 收件
优点：实现快、稳定。  
缺点：自动化不足，不满足核心体验。  
结论：不采用。

## 3. 架构与数据流

## 3.1 组件

1. Mac Poller（轮询采集器）
- 维护 watchlist（3 个会话）。
- 执行 UI 导航、消息区域截图、OCR 识别。
- 产生标准化消息事件。

2. Context Builder（上下文构建器）
- 为每个会话维护最近消息窗口。
- 组装 Prompt：最近上下文 + 风格规则 + 安全约束。

3. Reply Generator（生成器）
- 调 OpenAI 生成 2-3 条候选回复。
- 输出结构化结果：文本、风格标签、生成时间、简要理由。

4. Sync/API Service（同步服务）
- 接收消息事件与候选回复。
- 提供 iPhone 拉取接口。
- 存储去重指纹、会话状态、候选历史。

5. iPhone Receiver App（收件端）
- 展示会话列表、候选回复、更新时间。
- 支持一键复制。
- 支持一键改写（更简短/更正式/更随和）。

### 3.2 数据流
1. Mac Poller 轮询到会话 A 新消息。  
2. 标准化消息写入 Sync/API。  
3. Context Builder 组装上下文并触发生成。  
4. Reply Generator 调 OpenAI 返回候选。  
5. 候选写入 Sync/API。  
6. iPhone App 拉取并提醒用户。  
7. 用户复制后手动到微信发送。

## 4. 关键策略

### 4.1 轮询与调度
- 每会话基准轮询间隔 2-4 秒。
- 3 会话整轮目标小于等于 12 秒。
- 活跃会话提升优先级，静默会话降频。

### 4.2 新消息检测与去重
- 指纹：conversation_id + normalized_text + time_bucket。
- 双层去重：内存近期集合 + 持久层索引。
- 重试时通过指纹保证幂等。

### 4.3 上下文窗口
- 默认最近 30-50 条消息。
- Token 超限时优先保留：最新轮次、问句、用户近几条回复样式。
- 长文本使用摘要缓存减少成本。

### 4.4 回复风格可调（实时生效）
- 全局风格：默认语气、长度、禁用表达。
- 会话级覆盖：联系人单独风格。
- 即时改写：对单条候选二次生成（更简短/更正式/更随和）。
- 配置变更后下一次生成立即生效，无需重启。

### 4.5 输出策略
- 默认 2-3 条候选：主推荐 + 备选。
- 每条附短标签（如“澄清问题”“确认时间”“礼貌收束”）。
- 检测高风险承诺语句时添加提示标签。

## 5. 数据模型（逻辑）

### 5.1 ConversationConfig
- conversation_id
- display_name
- enabled
- poll_priority
- style_profile_id（可为空，回退全局）

### 5.2 MessageEvent
- event_id
- conversation_id
- direction（incoming/outgoing）
- text
- captured_at
- source_hash

### 5.3 CandidateReply
- candidate_id
- conversation_id
- based_on_event_ids
- variant_index
- text
- style_tag
- rationale_tag
- generated_at
- status（new/copied/dismissed）

### 5.4 StyleProfile
- style_profile_id
- tone
- brevity_level
- banned_phrases
- persona_hint
- updated_at

## 6. 错误处理与恢复

- OCR 失败：该会话本轮跳过并记录 error_code，下一轮自动重试。
- OpenAI 失败：指数退避重试，超过阈值后标记 degraded，不阻塞其他会话。
- 网络中断：本地暂存队列，恢复后按时间顺序补传。
- UI 漂移：检测关键锚点失败时触发“重新标定”流程。
- 重复推送风险：依赖指纹与状态机（new/copied/dismissed）抑制重复提醒。

## 7. 安全与隐私

- API Key 存储于 macOS Keychain。
- 传输全程 HTTPS。
- 日志默认脱敏（手机号、金额、证件号模式掩码）。
- iPhone 本地缓存可手动清空。
- 不支持自动发送，降低误操作与策略风险。

## 8. 测试与验收标准

### 8.1 功能验收
- 可配置并保存 3 个 watchlist 会话。
- 新消息可触发候选生成并同步到 iPhone。
- 复制按钮可稳定粘贴到微信。
- 全局风格、会话级风格、即时改写均生效。

### 8.2 正确性
- 去重：连续 100 条消息场景重复推送率低于 1%。
- 顺序：上下文不乱序。
- 隔离：A 会话内容不进入 B 会话 Prompt。
- 风格覆盖不串会话。

### 8.3 稳定性
- 连续运行 8 小时无崩溃。
- 网络波动可恢复。
- OCR 偶发失败不影响整体轮询。

### 8.4 性能
- 端到端延迟：P50 小于 8 秒，P95 小于 20 秒。
- 3 会话并发下资源占用可接受，不明显影响 Mac 日常操作。

### 8.5 通过门槛
- 连续 3 天真实使用稳定。
- 指标达标（延迟、重复率、恢复能力）。
- 用户主观可用性达到“可替代手工组织回复”。
